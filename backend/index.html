OpenMap API Documentation

API for gathering necessary data for OpenMap website development.

Global / Usage

Base URL (mounted prefix): https://openmap-backend.onrender.com/api/v1/{category}
Authentication: Send the API key using header x-api-key with each request. Example header: 

Authorization Header
x-api-key: [key]

All responses are JSON unless otherwise noted. Endpoints that accept an optional year parameter default to current year when omitted. Time and date formats follow ISO-8601 where applicable.

/api/v1/crime

GET /murderByState

Purpose: Return state-level murder totals and related FBI SHR data for a specified year.

Query ParameterTypeRequiredDescription
year string / integer No Four-digit year. Defaults to current year if omitted.

Response: JSON array of objects — one per state. Each object is the raw payload returned from the FBI SHR endpoint augmented with a state field containing the two-letter state code.

Notes: Requires an environment variable FBI_CRIME_KEY configured on the server. The shape of the FBI payload may change — consumers should rely on documented fields where possible.

/api/v1/lawEnforcement

GET /enforcementPopulation

Purpose: Retrieve police population / personnel statistics per state from the FBI personnel/employee endpoints for a given year.

Query ParameterTypeRequiredDescription
year string / integer No Four-digit year. Defaults to 2025.

Response: JSON array of objects — one per state. Each object contains the raw FBI personnel endpoint payload with an additional state field. Requires FBI_CRIME_KEY on the server.

GET /policeVictimCases

Purpose: Download and return the "people killed by police" case-level dataset (spreadsheet converted to JSON).

Behavior: The endpoint fetches an XLSX file from the external source and converts the first sheet into JSON rows. Each row corresponds to a case record with columns originating from the source dataset.

Response: JSON array of objects where each object maps column headers from the dataset to values for that case.

Notes: The external spreadsheet URL is defined inside the server code. Consumers must expect schema changes if the upstream dataset is updated. The server performs an in-memory conversion; large spreadsheets may increase memory usage.

GET /policeVictimDepts

Purpose: Download and return the dataset of police departments associated with people killed by police (spreadsheet sheet → JSON).

Behavior: Converts the second sheet of the XLSX resource into JSON rows and returns them.

Response: JSON array of department records as provided in the spreadsheet.

GET /policeVictimStates

Purpose: Download and return the aggregated state-level dataset of people killed by police (spreadsheet sheet → JSON).

Behavior: Converts the third sheet of the XLSX resource into JSON rows and returns them.

Response: JSON array of state-level aggregated records as provided by the spreadsheet.

Error Handling

On failure the API returns HTTP error statuses with a JSON body that contains an error field. Example:

{
  "error": { "message": "{{ERROR_MESSAGE_PLACEHOLDER}}", "details": "{{ERROR_DETAILS_PLACEHOLDER}}" }
}

Replace the placeholders above with the server's preferred error schema if different.

Operational Notes & Best Practices

  • Set FBI_CRIME_KEY and any other upstream API keys in environment configuration on the host.
  • Rate-limit or cache responses from external providers (FBI endpoints and XLSX host) to reduce latency and avoid throttling.
  • Validate and sanitize query parameters before passing them to upstream services.
  • Consider streaming or pagination for very large returned arrays.
